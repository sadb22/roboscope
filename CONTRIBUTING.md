# Совместная разработка

## Начало работы

1. Клонируйте репозиторий команды и перейдите в его каталог.
2. Установите Python 3.12.
3. Выполните локальный запуск из README.md. У каждого участника своя SQLite-база. Пароли и локальные проекты через Git не передаются.
4. Создайте рабочую ветку: `git switch -c feature/short-description`.

## Изменения и проверка

Перед началом задачи обновляйте main: `git switch main`, затем `git pull --ff-only`. Создавайте отдельную ветку для каждой задачи.

Перед отправкой изменений выполните:

```bash
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py test core
```

Если меняете расчёт, добавляйте проверку с независимо рассчитанным ожидаемым результатом и обновляйте docs/MODEL.md. При изменении структуры базы добавляйте миграцию. Не редактируйте уже применённые миграции.

Отправляйте ветку через `git push -u origin feature/short-description` и открывайте Pull Request. Один участник проверяет изменение, затем выполняется слияние. Рабочие изменения не отправляются напрямую в main. Проверки GitHub Actions запускаются автоматически после публикации репозитория.

## Распределение работы

- Python: расчёт, API, симуляция и проверки.
- SQL: модель данных, PostgreSQL, миграции и проверка резервных копий.
- Экономисты: допущения, сценарии, формулы и проверка денежного эффекта.
- Дизайн: static/app.css, templates/index.html, интерфейс и output/presentation.pptx.
- Ответственный за релиз: проверка полного сценария, развёртывание и доступность сервера.

Это зоны ответственности, а не ограничение прав. До изменения одного и того же файла согласуйте работу в команде. PPTX/PDF не сливаются построчно: их лучше редактировать одному участнику за раз.

## Что не отправлять в Git

.env, пароли, токены, локальную базу, реальные параметры клиентов, резервные копии, .venv и временные файлы. Настройки по умолчанию и пример окружения лежат в .env.example.

Исходные данные организатора включены для воспроизводимости. Репозиторий рекомендуется оставить приватным, пока команда не проверит условия их публичного распространения.

## Что GitHub не заменяет

GitHub хранит код и проверяет изменения. Приложению Django нужен отдельный сервер. GitHub Pages не запускает Python API, базу и обработчик симуляций. Инструкция сервера: docs/DEPLOYMENT.md.
