# Развёртывание и эксплуатация

## До запуска

1. Создать VPS с Linux, Docker Engine и Docker Compose. Ориентир: 4 vCPU, 8 ГБ RAM, 80 ГБ SSD.
2. Создать DNS A-запись домена на публичный IPv4 сервера. Не создавать AAAA-запись, если IPv6 не настроен.
3. Разрешить входящие 80/443 и SSH только администраторам. Порты базы и приложения не публикуются.
4. Скопировать исходный проект на сервер. Не переносить `.venv`, локальную SQLite-базу или чужой `.env`.

## Запуск

```bash
python3 scripts/configure.py --domain your-domain.ru
docker compose config --quiet
docker compose up -d --build
docker compose ps
docker compose logs --tail=100 web worker proxy
```

Конфигурационный скрипт создаёт случайные пароли и секрет Django в `.env` с доступом только владельцу. Повторный запуск не перезаписывает файл. Пароль администратора находится в ADMIN_PASSWORD, пароль демонстрационного пользователя — DEMO_PASSWORD. Передавать демонстрационный пароль жюри отдельно от доступа администратора.

Контейнер migrate применяет миграции и загружает демонстрационный каталог. Повторный запуск не сбрасывает каталог, нормативы или пароли пользователей. Caddy автоматически получает HTTPS-сертификат для домена. База хранится в отдельном Docker volume.

После изменения кода: `docker compose up -d --build`. Проверить `/health/`, вход, расчёт, сохранение проекта, PDF и новый прогон симуляции.

## Резервные копии

Сервис backup делает pg_dump при запуске и затем каждые 24 часа в каталог `backups/`. Для недели оценки храним все копии. Копировать их во внешнее защищённое хранилище: резервная копия на том же сервере не защищает от потери VPS.

Проверка копии: `docker compose exec -T db pg_restore --list` с подачей файла через stdin. Восстановление выполнять сначала в отдельную базу. Восстановление поверх рабочей базы требует остановки записи, резервного копирования текущего состояния и явного решения администратора.

## Доступность

Настроить внешний HTTP-монитор на `https://your-domain.ru/health/` с интервалом 1–5 минут и уведомлением ответственному. Endpoint проверяет приложение и базу. Для очереди проверять `/api/worker-health/` под администратором или журналы worker. Сервис должен оставаться оплаченным как минимум до конца 6 октября 2026 года.

Во время оценки ежедневно проверять свободное место, выполнение резервной копии, доступность HTTPS и очередь симуляций. `restart: unless-stopped` обеспечивает перезапуск контейнеров; Docker Engine также должен запускаться при перезагрузке сервера.

## Завершение

После окончания оценки экспортировать проекты и сделать финальный дамп. Отключение и удаление сервера, копий и домена выполняет владелец аккаунта. Автоматическое удаление не настроено.

## Проверяемые ограничения

Один VPS не является кластером высокой доступности. Производительность и выпуск сертификата требуется подтвердить на целевом сервере. Бесплатный временный туннель с ноутбука не используется как размещение для жюри.
